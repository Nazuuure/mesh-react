# Контур · CPS Group
Четыре самостоятельных сайта с общей базой для совместной демонстрации в локальной сети. Один компьютер запускает сервер, остальные открывают адрес своей роли в браузере.

## Запуск
Откройте терминал в папке mesh. Для Docker с PostgreSQL выполните `docker compose up --build`. Для запуска с Node.js 24 и SQLite достаточно `node server.mjs`, никаких npm-пакетов для этого режима не требуется. Используйте один экземпляр сервера. При обновлении существующей установки остановите предыдущий процесс; сохраните mesh.sqlite или том PostgreSQL. Первый запуск Docker требует интернета.

| Роль | На компьютере сервера | На других ПК, пример |
|---|---|---|
| Покупатель | http://localhost:8000 | http://192.168.1.50:8000 |
| Продавец | http://localhost:8001 | http://192.168.1.50:8001 |
| WB | http://localhost:8002 | http://192.168.1.50:8002 |
| ПВЗ | http://localhost:8003 | http://192.168.1.50:8003 |

На Windows выполните `ipconfig` и замените 192.168.1.50 на IPv4-адрес Wi-Fi или Ethernet компьютера с сервером. Все участники подключаются к одной локальной сети. Если Windows запросит сетевой доступ, разрешите его для частной сети. Нужны входящие TCP-подключения на четыре указанных порта. Роли без паролей предназначены для доверенной сети команды. В режиме Node при занятых портах в cmd выполните `set PORT=8081`, затем `node server.mjs`; адреса будут 8081–8084. В Compose по умолчанию опубликованы 8000–8003. Для тестов выполните `node --test test.mjs`.

## Показ за одним столом
1. Покупатель заказывает рюкзак City в Заречный. Товар на хабе. Диспетчер отмечает появившуюся заявку, назначение «На выдачу по заказу», ПВЗ Заречный и запрашивает приёмку.
2. Сотрудник Заречного соглашается принять партию. WB видит её в «Передаче груза» и подтверждает отправку с хаба. На сайтах покупателя, WB и принимающего ПВЗ появляется ход доставки. Через 25 секунд сотрудник подтверждает получение. Покупатель видит готовность к выдаче. Сотрудник выдаёт заказ. Литры в зоне выдачи и ёмкость мини-склада учитываются раздельно.
3. Для хранения продавец создаёт карточку с габаритами 20 × 10 × 5 см. Интерфейс показывает 1 л на упаковку. Разместите 3 упаковки на хабе и запросите их перемещение. WB согласует поставку на хранение. Проверьте резерв места до отправки и занятую ёмкость после приёмки.
4. Для робота создайте заявку продавца на три упаковки между городскими ПВЗ. Диспетчер назначает робота и подтверждает маршрут. Исходный ПВЗ подтверждает отправку. Время пути — 10 секунд до первой остановки, ещё 10 секунд до каждой следующей. Каждый принимающий ПВЗ подтверждает свои строки партии после прибытия. Повторный клик не начисляет остаток второй раз.

## Правила учёта и времени
- Литраж новой карточки = длина × ширина × высота в см / 1000. Сервер рассчитывает его самостоятельно. Существующие карточки сохраняют ранее принятый объём.
- «На выдачу» предназначено для адресных заказов покупателей. «На хранение» резервирует вместимость мини-склада. «По заявкам» выбирает выдачу для заказа и хранение для запаса продавца, в том числе в смешанной партии. Отказ в предварительном согласовании перенаправляет заявку. Приёмка в промежуточном ПВЗ запускает предложение покупателю забрать заказ там.
- Один модельный день проходит за 120 реальных секунд. Для доставки используются общие серверные отметки времени. После таймера нужно подтверждение получателя; закрытие вкладки не прерывает перевозку. Диспетчер может вручную прибавить день для проверки стоимости хранения.
- Отправитель хаба — диспетчер, отправитель городского ПВЗ — сотрудник исходного пункта. Получатель — сотрудник выбранного ПВЗ. Назначение роли задаёт сервер по адресу сайта. Отдельных персональных аккаунтов нет.
- Обновления поступают в открытые вкладки примерно каждую 1,2 секунды. Одновременные записи сериализуются; при изменении версии устаревшая команда отклоняется. Все четыре сайта используют один экземпляр PostgreSQL или SQLite.
- Перевозка считается по модели 360 ₽/рейс с распределением на коробки или 80 ₽ за единицу через хаб. Малая партия робота допускается после модельных суток. Параметры, история спроса и схема города — учебные.
- Сброс демоданных выполняется на сайте WB в «Управлении демонстрацией». Сброс общий для всех участников.

## План пилота
Одна пара городских ПВЗ, затем несколько точек одного города. Считать поток по часам, фактическую загрузку рейса, полную стоимость выданного заказа относительно хаба, срок до выдачи и число отказов в приёмке. Пример оценки: 50 ПВЗ × 100 заказов/сутки × 8 записей на заказ = 40 000 операций/сутки, около 0,46 записи/с в среднем и 4,6 при десятикратном пике. Это оценка, а не результат нагрузочного теста. Для сети заменить общий снимок отдельными таблицами и транзакциями по партиям, добавить индексы по городу, статусу и ПВЗ, проверку прав на сервере, журнал событий, метрики задержки и ошибок, резервное копирование и проверку восстановления. Текущий режим без паролей рассчитан на локальную демонстрацию.
