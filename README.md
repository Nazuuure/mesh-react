# Контур · Mesh React

Четыре кабинета на React и TypeScript используют один сервер Node.js и общую базу данных.

## Запуск через Docker

```sh
docker compose up --build -d
```

Compose соберёт интерфейс, запустит сервер и PostgreSQL. Состояние сохраняется в томе `mesh_data`. Для остановки выполните `docker compose stop`.

| Кабинет | Адрес |
|---|---|
| Покупатель | http://127.0.0.1:8000/buyer/ |
| Продавец | http://127.0.0.1:8000/seller/ |
| Диспетчер WB | http://127.0.0.1:8000/wb/ |
| Сотрудник ПВЗ | http://127.0.0.1:8000/pvz/ |

Если порт 8000 занят, перед запуском задайте другой порт через переменную `MESH_PORT`. Например, в PowerShell выполните `$env:MESH_PORT = '8011'` и откройте кабинет на порту 8011.

## Разработка

Установите Node.js 24. Для локального запуска с SQLite выполните:

```sh
npm ci
npm run build
npm start
```

Для разработки интерфейса с быстрым обновлением запустите `npm start` и в другом терминале `npm run dev`. Vite покажет адрес интерфейса и передаст запросы к API серверу на порту 8000. Если сервер использует другой `PORT`, задайте его в обоих терминалах.

- `frontend/src/components` содержит страницы и общие элементы интерфейса. Стили хранятся в соседних CSS Modules.
- `frontend/src/hooks` содержит состояние экранов, формы, обновление данных и часы.
- `frontend/src/functions` содержит расчёты каталога, логистики и карт.
- `frontend/src/types.ts` описывает снимок состояния и команды.
- `model.mjs` отвечает за статусы, рейсы, остатки и начисления. `server.mjs` обслуживает `GET /api/state` и `POST /<роль>/api/actions`.

Проверки выполняются командами `npm test` и `npm run build`.

## Сравнение маршрутов для защиты

Откройте кабинет WB и блок «Сравнение Mesh и хаба». Сравнивается одна партия одинаковых заказов: одна упаковка на заказ, те же объём, масса и число возвратов. Сроки хранения по маршрутам можно задать отдельно. Время до готовности включает ожидание отгрузки, расчётное движение, обработку и задержку из-за сбоя.

Учебный пример: упаковка 1 л и 1 кг, хранение 7 дней по обоим маршрутам, первая остановка, комплектация Mesh 30 с, ожидание хаба 15 с и без сбоев. Оба маршрута укладываются в 50 с при лимите 90 с.

| Заказов | Mesh, ₽ за партию | Хаб, ₽ за партию | Экономия Mesh, ₽ на заказ |
|---:|---:|---:|---:|
| 3 | 436,50 | 316,50 | −40 |
| 5 | 487,50 | 527,50 | +8 |
| 8 | 564,00 | 844,00 | +35 |
| 14 | 717,00 | 1 477,00 | +54,29 |

Хранение, обработка, выдача и возвраты учитываются с обеих сторон. При одинаковых условиях порог определяется перевозкой: рейс ровера стоит 360 ₽, а хаб — 80 ₽ на заказ. От пяти упаковок ровер дешевле. Один выезд курьера за 60 ₽ сдвигает порог до шести, а выезд курьера и один сорванный рейс — до десяти. Рекомендация также учитывает срок, объём и массу груза. Оценка в очереди WB использует 90 с как учебный лимит и считает одинаковыми затраты на хранение по обоим вариантам.

Остаток теперь ведётся партиями для каждого пункта. При выдаче и отгрузке первыми списываются старшие партии. Перемещение сохраняет уже накопленные дни хранения, перевозка и ожидание в зоне выдачи дополнительных дней не добавляют. Для остатков, сохранённых до обновления, начальная партия получает дату старой карточки как оценку поступления.


## Показ за одним столом
1. Оформите заказ на рюкзак City в Заречный. При наличии на хабе сервер назначает поставку на выдачу. Сотрудник выбирает хаб в кабинете ПВЗ и подтверждает отправку, а получатель после прибытия подтверждает приёмку и выдаёт заказ.
2. Для проверки балансировки продвиньте модельное время. Целевой запас артикула равен числу заказов этого артикула в точку за последние 7 модельных дней за вычетом возвращённых. Свободные партии от 14 дней хранения на месте или излишек при заполнении от 90% перераспределяются в точки с дефицитом с учётом ожидаемых поставок и вместимости. Оставшийся излишек возвращается на хаб. Хаб пополняет дефицит из свободного запаса.
3. Создайте городское перемещение менее шести упаковок. Через 60 секунд сервер назначает плечо до хаба. После физической приёмки на хабе появляется поставка в конечный ПВЗ. При частичной приёмке вводится суммарное число полученных упаковок по поставке. API принимает приращение `received` и уникальный для этой поставки `eventId` для повторной доставки события без двойного зачисления.
4. У продавца выберите город размещения по карте спроса. Сервер подбирает ПВЗ по спросу категории и свободному объёму. Для городского рейса наберите от шести совместимых упаковок из одного ПВЗ. Через семь секунд сервер назначит свободного ровера. Исходный ПВЗ подтверждает погрузку и отправку. Время пути — 10 секунд до первой остановки, ещё 10 секунд до каждой следующей. Каждый принимающий ПВЗ подтверждает свои строки партии после прибытия. Повторный клик не начисляет остаток второй раз.

5. В кабинете WB выберите «Симулировать застревание» у ровера в пути. На карте остановится маркер. Кнопка «Отправить курьера» фиксирует выезд и начисляет его стоимость. После помощи диспетчер нажимает «Подтвердить помощь и продолжить рейс». Сотрудник ПВЗ принимает груз обычным способом после прибытия.

## Правила учёта и времени
- Литраж новой карточки = длина × ширина × высота в см / 1000. Сервер рассчитывает его самостоятельно. Существующие карточки сохраняют ранее принятый объём.
- «На выдачу» предназначено для адресных заказов покупателей. «На хранение» резервирует вместимость мини-склада. «По заявкам» выбирает выдачу для заказа и хранение для запаса продавца, в том числе в смешанной партии. Отказ в предварительном согласовании перенаправляет заявку. Приёмка в промежуточном ПВЗ запускает предложение покупателю забрать заказ там.
- Один модельный день проходит за 120 реальных секунд. Для доставки используются общие серверные отметки времени. После таймера нужно подтверждение получателя; закрытие вкладки не прерывает перевозку. Диспетчер может вручную прибавить день для проверки стоимости хранения.
- Отправитель хаба — диспетчер, отправитель городского ПВЗ — сотрудник исходного пункта. Получатель — сотрудник выбранного ПВЗ. Назначение роли задаёт сервер по адресу сайта. Отдельных персональных аккаунтов нет.
- Обновления поступают в открытые вкладки примерно каждую 1,2 секунды. Одновременные записи сериализуются; при изменении версии устаревшая команда отклоняется. Все четыре сайта используют один экземпляр PostgreSQL или SQLite.
- Перевозка считается по модели 360 ₽/рейс с распределением на коробки или 80 ₽ за единицу через хаб. В деморежиме рейс назначается автоматически от 6 упаковок с окном сбора 7 секунд. Багажник вмещает 61 л, допустимая масса груза — 25 кг. Продавец указывает массу одной упаковки. Для демотоваров и прежних карточек без массы принято учебное значение 1 кг за упаковку. Параметры, история спроса и схема города — учебные.
- Сброс демоданных выполняется на сайте WB в «Управлении демонстрацией». Сброс общий для всех участников.

## План пилота
Одна пара городских ПВЗ, затем несколько точек одного города. Считать поток по часам, фактическую загрузку рейса, полную стоимость выданного заказа относительно хаба, срок до выдачи и число отказов в приёмке. Пример оценки: 50 ПВЗ × 100 заказов/сутки × 8 записей на заказ = 40 000 операций/сутки, около 0,46 записи/с в среднем и 4,6 при десятикратном пике. Это оценка, а не результат нагрузочного теста. Для сети заменить общий снимок отдельными таблицами и транзакциями по партиям, добавить индексы по городу, статусу и ПВЗ, проверку прав на сервере, журнал событий, метрики задержки и ошибок, резервное копирование и проверку восстановления. Текущий режим без паролей рассчитан на локальную демонстрацию.


Для панели «Камера ровера» в кабинете WB задайте ROVER_R01_CAMERA_URL или ROVER_R02_CAMERA_URL перед запуском сервера. Используйте адрес видеопотока, доступный браузеру участников и поддерживаемый HTML video. Ссылка видна клиентам демонстрационного сервера. Панель показывает камеры активных рейсов. В Docker Compose эти переменные передаются веб-сервису из окружения.
